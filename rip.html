Лаб №3. Динамическая маршрутизация RIP

Реализация сетей в Linux. Продолжение Части 3: та же схема и конфигурация FRR, на маршрутизаторах статика заменяется на RIPv2.

1. Схема стенда

сеть A /28   сеть B /30   сеть C /29  ·  «Net N» — подпись кабеля/гнезда на стенде, в конфигах не используется.

3. Суть работы

Лаб №3 — это Часть 3 (статическая маршрутизация с FRR) плюс несколько строк. Адреса, шлюзы по умолчанию на рабочих станциях, ip forwarding и сохранение — всё как в Части 3. На маршрутизаторах статические маршруты заменяются протоколом RIP: маршрутизаторы сами сообщают друг другу о своих сетях.
МашинаЧто меняется по сравнению с Частью 3
ПК1, ПК2Ничего (адрес + ip route 0.0.0.0/0 <шлюз>)
R1, R2Включить демон ripd; убрать ip route …; добавить блок router rip

4. База: Часть 3

Если стенд после Части 3 уже настроен и сохранён — сразу к п. 5. Если начинаете с нуля (после timeshift --restore), сначала выполните гайд Части 3 до сохранения конфигурации. Пункт с ip route на маршрутизаторах (п. 8 Части 3) можно пропустить — его заменит RIP.

Проверка, что база в порядке (на каждом маршрутизаторе):

sudo vtysh -c 'show running-config'

Должны быть адреса интерфейсов и ip forwarding.

5. Дописываем: включить ripd (R1 и R2)

В обычном терминале. Перед этим конфигурация должна быть сохранена (copy running-config startup-config), иначе при перезапуске FRR несохранённое пропадёт.

sudo sed -i 's/^ripd=no/ripd=yes/' /etc/frr/daemons
sudo systemctl restart frr
grep ^ripd /etc/frr/daemons

Должно быть ripd=yes.

6. Дописываем: RIP в vtysh

Те самые «пара строк». Строку no ip route вводить, только если статический маршрут остался с Части 3 (иначе он перебьёт RIP: у статики административное расстояние 1, у RIP — 120).

R1 сети A и B

sudo vtysh
configure terminal
no ip route 10.0.0.16/29 10.0.0.26
router rip
version 2
network 10.0.0.0/28
network 10.0.0.24/30
end
copy running-config startup-config

R2 сети B и C

sudo vtysh
configure terminal
no ip route 10.0.0.0/28 10.0.0.25
router rip
version 2
network 10.0.0.24/30
network 10.0.0.16/29
end
copy running-config startup-config
version 2 обязательно: подсети разной длины (/28, /30, /29), а RIP версии 1 масок не передаёт.

Итог в show running-config на R1 — к конфигурации Части 3 добавилось:

router rip
 version 2
 network 10.0.0.0/28
 network 10.0.0.24/30
exit

7. Проверка RIP

Обновления RIP рассылаются раз в 30 секунд — подождите до минуты.

show ip rip
show ip route

R1 — show ip route

C>* 10.0.0.0/28 is directly connected, enp1s0
R>* 10.0.0.16/29 [120/2] via 10.0.0.26, enp4s0
C>* 10.0.0.24/30 is directly connected, enp4s0

R2 — show ip route

R>* 10.0.0.0/28 [120/2] via 10.0.0.25, enp1s0
C>* 10.0.0.16/29 is directly connected, enp3s0
C>* 10.0.0.24/30 is directly connected, enp1s0

R — маршрут получен по RIP, [120/2] — административное расстояние / метрика (число переходов). Формат вывода может немного отличаться.

8. Проверка связи

С ПК1

ping -c 3 10.0.0.19
traceroute 10.0.0.19

10.0.0.3 → 10.0.0.26 → 10.0.0.19

С ПК2

ping -c 3 10.0.0.1
traceroute 10.0.0.1

10.0.0.17 → 10.0.0.25 → 10.0.0.1

10. Кратко для защиты

  • RIP — дистанционно-векторный протокол динамической маршрутизации: маршрутизаторы каждые 30 секунд рассылают соседям свою таблицу маршрутов.
  • Метрика — число переходов (hop count); максимум 15, 16 — сеть недостижима. Поэтому RIP подходит только для небольших сетей.
  • RIPv2 передаёт маски подсетей (поддержка VLSM/CIDR) и использует multicast 224.0.0.9; RIPv1 масок не передаёт.
  • Административное расстояние: подключённая сеть — 0, статика — 1, RIP — 120. При наличии статического маршрута RIP-маршрут в ту же сеть не используется.
  • Отличие от статики: маршруты не прописываются вручную и перестраиваются сами при изменении сети.
  • ip forwarding — разрешение пересылки пакетов между интерфейсами; copy running-config startup-config — сохранение текущей конфигурации в /etc/frr/frr.conf.
