Маршрутизация через FRR (OSPF): ПК1 → R1 → R2 → ПК2

Лабораторная работа «Реализация сетей в Linux». Та же схема, но маршруты между R1 и R2 строит FRR по протоколу OSPF. Все шаги: от restore и установки пакета через вузовскую сеть до пинга.

← Вариант со статическими маршрутами

1. Схема стенда

сеть A /28   сеть B /30   сеть C /29  ·  «Net N» — подпись кабеля/гнезда на стенде, в конфигах не используется.

2. Таблица адресации

Подсети не пересекаются: 0–15, 16–23, 24–27. Сеть /30 между маршрутизаторами — ровно на два адреса, по одному на каждый конец канала.

3. Что меняется по сравнению со статикой

ПК1 и ПК2 — настраиваются так же: адрес + шлюз по умолчанию.
R1 и R2 — в Netplan только адреса, без блока routes. Маршруты в чужие сети маршрутизаторы узнают друг от друга сами по протоколу OSPF, который запускает пакет FRR.
FRR ставится только на два компьютера-маршрутизатора (R1 и R2).

4. Порядок работы

  1. restore на всех машинах (как в начале каждой лабораторной) — система возвращается в чистое состояние, FRR после этого нет.
  2. R1 и R2 по очереди (или одновременно) подключить шнуром к вузовской сети и поставить FRR (п. 5).
  3. Отключить вузовский шнур, собрать стенд по схеме, проверить, в какие интерфейсы воткнуты кабели (п. 6).
  4. Netplan → ip_forward → OSPF → проверка → пинг (п. 7–12).
Не перезагружать машины после restore до конца работы. Если restore срабатывает при перезагрузке, FRR и все настройки пропадут — придётся ставить заново.

5. Установка FRR через вузовский интернет (R1 и R2)

  1. Воткнуть кабель вузовской сети в любой сетевой порт маршрутизатора.
  2. Посмотреть, на каком интерфейсе есть линк (LOWER_UP / UP) и получен ли адрес по DHCP: 
    ip -br link
ip -br a
  3. Проверить интернет: 
    ping -c 3 ya.ru
    Если адреса нет или пинг не идёт — запросить адрес по DHCP вручную (подставить свой интерфейс): 
    sudo dhclient -v enp1s0
    Если команды dhclient нет — переподключить сеть в графическом апплете XFCE (значок сети в панели) или выполнить sudo netplan apply.
  4. Поставить FRR: 
    sudo apt update
sudo apt install -y frr
  5. Проверить установку: 
    systemctl status frr --no-pager
which vtysh
  6. Вынуть вузовский кабель.
Если в аудитории один вузовский шнур — ставим FRR сначала на R1, потом перекладываем шнур на R2. ПК1 и ПК2 интернет не нужен.

6. Сборка стенда и проверка интерфейсов (все четыре машины)

  1. Подключить кабели по схеме (Net 0 / Net 1 / Net 2).
  2. Убедиться, что линк есть именно на нужных интерфейсах — у них должно быть UP: 
    ip -br link
    Если UP на другом интерфейсе, чем в таблице, — кабель воткнут не в тот порт: переткнуть кабель или поменять имя интерфейса в конфиге Netplan.
  3. Убрать старые конфиги Netplan с теми же интерфейсами (после restore там может быть DHCP-конфиг): 
    ls /etc/netplan/
sudo mv /etc/netplan/50-cloud-init.yaml /etc/netplan/50-cloud-init.yaml.bak
    Имя файла может быть другим (01-network-manager-all.yaml и т.п.) — переносится любой, кроме нашего 01-lab.yaml.

7. Netplan

ПК1 enp4s0 · 10.0.0.1/28

sudo tee /etc/netplan/01-lab.yaml > /dev/null <<'EOF'
network:
  version: 2
  renderer: networkd
  ethernets:
    enp4s0:
      addresses: [10.0.0.1/28]
      routes:
        - to: default
          via: 10.0.0.3
EOF

ПК2 enp1s0 · 10.0.0.19/29

sudo tee /etc/netplan/01-lab.yaml > /dev/null <<'EOF'
network:
  version: 2
  renderer: networkd
  ethernets:
    enp1s0:
      addresses: [10.0.0.19/29]
      routes:
        - to: default
          via: 10.0.0.17
EOF

R1 только адреса, без routes

sudo tee /etc/netplan/01-lab.yaml > /dev/null <<'EOF'
network:
  version: 2
  renderer: networkd
  ethernets:
    enp1s0:
      addresses: [10.0.0.3/28]
    enp4s0:
      addresses: [10.0.0.25/30]
EOF

R2 только адреса, без routes

sudo tee /etc/netplan/01-lab.yaml > /dev/null <<'EOF'
network:
  version: 2
  renderer: networkd
  ethernets:
    enp1s0:
      addresses: [10.0.0.26/30]
    enp3s0:
      addresses: [10.0.0.17/29]
EOF

Применить на всех четырёх:

sudo chmod 600 /etc/netplan/01-lab.yaml
sudo netplan apply

Сразу проверить, что адреса встали и не потерялись при перетыкании кабелей:

ip -br a

У каждого нужного интерфейса должны быть статус UP и адрес из таблицы. Если адреса нет (кабель переткнули, линк пропадал) — ещё раз sudo netplan apply. Если на интерфейсе висит лишний адрес вроде 192.168.x.x или 169.254.x.x от вузовской сети — это остатки DHCP: перенести старые конфиги Netplan (п. 6) и снова sudo netplan apply.

Старый Netplan не принимает to: default — тогда на ПК1 пишется gateway4: 10.0.0.3, на ПК2 gateway4: 10.0.0.17.

8. Пересылка пакетов (только R1 и R2)

sudo sysctl -w net.ipv4.ip_forward=1

Ответ net.ipv4.ip_forward = 1 — включено. После перезагрузки выполнить снова.

9. Включить OSPF в FRR (R1 и R2)

По умолчанию в FRR работают только служебные демоны. Включаем демон ospfd и перезапускаем FRR:

sudo sed -i 's/^ospfd=no/ospfd=yes/' /etc/frr/daemons
sudo systemctl restart frr
grep ^ospfd /etc/frr/daemons

Последняя команда должна показать ospfd=yes.

10. Настройка OSPF

Каждый маршрутизатор объявляет в OSPF свои подключённые сети (area 0). Блок вставляется целиком — это одна команда vtysh с несколькими -c; в конце конфигурация сохраняется (write memory → /etc/frr/frr.conf).

R1 сети A и B

sudo vtysh \
  -c 'configure terminal' \
  -c 'router ospf' \
  -c 'ospf router-id 1.1.1.1' \
  -c 'network 10.0.0.0/28 area 0' \
  -c 'network 10.0.0.24/30 area 0' \
  -c 'end' \
  -c 'write memory'

R2 сети B и C

sudo vtysh \
  -c 'configure terminal' \
  -c 'router ospf' \
  -c 'ospf router-id 2.2.2.2' \
  -c 'network 10.0.0.24/30 area 0' \
  -c 'network 10.0.0.16/29 area 0' \
  -c 'end' \
  -c 'write memory'

То же самое вручную в консоли vtysh

Если преподаватель хочет видеть ввод по шагам (на примере R1):

sudo vtysh
configure terminal
router ospf
ospf router-id 1.1.1.1
network 10.0.0.0/28 area 0
network 10.0.0.24/30 area 0
end
write memory
exit

11. Проверка OSPF (R1 и R2)

Соседство поднимается не сразу — подождать до 40 секунд.

sudo vtysh -c 'show ip ospf neighbor'

Должен быть виден сосед (на R1 — 2.2.2.2, на R2 — 1.1.1.1) в состоянии Full.

sudo vtysh -c 'show ip route ospf'
ip r

В ip r на маршрутизаторе снова три строки, но маршрут в чужую сеть помечен proto ospf:

R1 — ip r

10.0.0.0/28 dev enp1s0 proto kernel scope link src 10.0.0.3
10.0.0.16/29 via 10.0.0.26 dev enp4s0 proto ospf metric 20
10.0.0.24/30 dev enp4s0 proto kernel scope link src 10.0.0.25

R2 — ip r

10.0.0.0/28 via 10.0.0.25 dev enp1s0 proto ospf metric 20
10.0.0.16/29 dev enp3s0 proto kernel scope link src 10.0.0.17
10.0.0.24/30 dev enp1s0 proto kernel scope link src 10.0.0.26

Значение metric может отличаться — главное, что строка с via и proto ospf есть.

12. Пинг

С ПК1 по цепочке:

ping -c 3 10.0.0.3     # R1, вход
ping -c 3 10.0.0.26    # R2, вход
ping -c 3 10.0.0.19    # ПК2 — цель
tracepath 10.0.0.19

Прыжки: 10.0.0.3 → 10.0.0.26 → 10.0.0.19. Обратно — с ПК2: ping -c 3 10.0.0.1.

14. Кратко для защиты

  • FRR — пакет динамической маршрутизации для Linux (OSPF, BGP, RIP и др.); zebra передаёт найденные маршруты в ядро, ospfd работает по OSPF, vtysh — общая консоль настройки.
  • OSPF — протокол состояния каналов: маршрутизаторы находят соседей, обмениваются сведениями о сетях и сами строят таблицу маршрутов.
  • Отличие от статики: маршруты не прописываются вручную; при добавлении новой сети достаточно объявить её командой network.
  • router-id — уникальный идентификатор маршрутизатора в OSPF; area 0 — магистральная (основная) область.
  • Конечным ПК OSPF не нужен — им достаточно шлюза по умолчанию.
