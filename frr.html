Часть 3. Статическая маршрутизация с пакетом FRR

Реализация сетей в Linux. Все настройки — в консоли vtysh на четырёх машинах, по пунктам методички: от timeshift --restore до перезагрузки и проверки.

1. Схема стенда

сеть A /28   сеть B /30   сеть C /29  ·  «Net N» — подпись кабеля/гнезда на стенде, в конфигах не используется.

2. Таблица адресации

УстройствоКабельИнтерфейсIP / маскаСетьКоманда маршрута в vtysh
ПК1Net 0enp4s010.0.0.1/28Aip route 0.0.0.0/0 10.0.0.3
R1Net 1enp1s010.0.0.3/28A—
Net 0enp4s010.0.0.25/30Bip route 10.0.0.16/29 10.0.0.26
R2Net 1enp1s010.0.0.26/30Bip route 10.0.0.0/28 10.0.0.25
Net 2enp3s010.0.0.17/29C—
ПК2Net 1enp1s010.0.0.19/29Cip route 0.0.0.0/0 10.0.0.17

Расчёт подсетей

СетьМаскаАдрес сетиУзлыBroadcastУзлов
A (ПК1 — R1)/28 = 255.255.255.24010.0.0.010.0.0.1 – 10.0.0.1410.0.0.1514
C (R2 — ПК2)/29 = 255.255.255.24810.0.0.1610.0.0.17 – 10.0.0.2210.0.0.236
B (R1 — R2)/30 = 255.255.255.25210.0.0.2410.0.0.25 – 10.0.0.2610.0.0.272

Подсети не пересекаются: 0–15, 16–23, 24–27. Сеть /30 между маршрутизаторами — ровно на два адреса, по одному на каждый конец канала.

3. Порядок работы

По методичке FRR ставится на все четыре машины: IP-адреса, маршрут по умолчанию на рабочих станциях, статические маршруты и включение маршрутизации — всё делается в консоли FRR vtysh. Netplan в этой части не используется.
  1. 0Restore на всех машинах.
  2. 0Через вузовскую сеть поставить frr на все 4 машины, вынуть вузовский шнур, собрать стенд.
  3. 1–2В vtysh назначить IP-адреса интерфейсам.
  4. 3Пропинговать ближайших соседей.
  5. 4На рабочих станциях — маршрут по умолчанию.
  6. 8На маршрутизаторах — статические маршруты.
  7. 9Включить маршрутизацию (ip forwarding).
  8. 10Проверить ping и traceroute: ПК1 и ПК2 пингуют друг друга.
  9. 11Сохранить: copy running-config startup-config.
  10. 12Перезагрузиться и проверить, что всё работает.

4. Restore (все машины)

sudo timeshift --restore

Timeshift спросит, какой снимок восстановить, и попросит подтверждение — выбрать снимок, который используется на стенде, и подтвердить. После восстановления система перезагружается.

5. Установка FRR (все машины, через вузовскую сеть)

  1. Воткнуть кабель вузовской сети в машину, проверить адрес и интернет: 
    ip -br a
ping -c 3 ya.ru
    Если адреса нет — запросить по DHCP (подставить свой интерфейс): sudo dhclient -v enp1s0.
  2. Поставить FRR и traceroute (traceroute понадобится в п. 10, после отключения интернета его уже не поставить): 
    sudo apt update
sudo apt install -y frr traceroute
  3. Проверить, что FRR запущен: 
    systemctl status frr --no-pager
  4. Вынуть вузовский кабель, переложить его на следующую машину. Когда FRR стоит на всех 4 — собрать стенд по схеме.
Для статических маршрутов отдельные демоны включать не нужно: zebra (интерфейсы, адреса, forwarding) и staticd (команда ip route) запускаются в FRR всегда.

6. Проверка кабелей (все машины)

ip -br link

Статус UP должен быть на интерфейсах из таблицы. Если UP на другом интерфейсе — кабель не в том порту: переткнуть его (или использовать в vtysh фактическое имя интерфейса).

7. Пункты 1–2. Назначение IP-адресов в vtysh

Вход в консоль FRR и режим настройки (config = configure terminal):

ПК1

sudo vtysh
config
interface enp4s0
ip address 10.0.0.1/28
exit
end

ПК2

sudo vtysh
config
interface enp1s0
ip address 10.0.0.19/29
exit
end

R1

sudo vtysh
config
interface enp1s0
ip address 10.0.0.3/28
exit
interface enp4s0
ip address 10.0.0.25/30
exit
end

R2

sudo vtysh
config
interface enp1s0
ip address 10.0.0.26/30
exit
interface enp3s0
ip address 10.0.0.17/29
exit
end

Проверка (из vtysh): адреса и состояние интерфейсов.

show interface brief
Консоль vtysh можно не закрывать — все дальнейшие команды вводятся в ней же. Чтобы выполнить обычную команду Linux (ping), откройте второй терминал или выйдите из vtysh командой exit.

8. Пункт 3. Пинг ближайших соседей

В обычном терминале (не в vtysh):

С машиныКомандаКого проверяем
ПК1ping -c 3 10.0.0.3R1 (сеть A)
R1ping -c 3 10.0.0.1 и ping -c 3 10.0.0.26ПК1 и R2
R2ping -c 3 10.0.0.25 и ping -c 3 10.0.0.19R1 и ПК2
ПК2ping -c 3 10.0.0.17R2 (сеть C)

Все соседи должны отвечать. Если нет — кабель, порт или адрес (п. 6–7). Дальние узлы на этом шаге ещё не пингуются — маршрутов пока нет.

9. Пункт 4. Маршрут по умолчанию на рабочих станциях

ПК1 шлюз — R1

sudo vtysh
conf
ip route 0.0.0.0/0 10.0.0.3
end

ПК2 шлюз — R2

sudo vtysh
conf
ip route 0.0.0.0/0 10.0.0.17
end

10. Пункт 8. Статические маршруты на маршрутизаторах

Каждому маршрутизатору нужен маршрут в ту сеть, к которой он не подключён: ip route <сеть/маска> <IP следующего маршрутизатора>.

R1 сеть C — через R2

sudo vtysh
conf
ip route 10.0.0.16/29 10.0.0.26
end

R2 сеть A — через R1

sudo vtysh
conf
ip route 10.0.0.0/28 10.0.0.25
end

11. Пункт 9. Включение маршрутизации (R1 и R2)

sudo vtysh
conf
ip forwarding
end

Проверка: в show running-config есть строка ip forwarding (или в Linux: cat /proc/sys/net/ipv4/ip_forward → 1).

12. Пункт 10. Проверка: ping и traceroute

Таблица маршрутизации в vtysh — show ip route. Пример для R1 (формат может немного отличаться):

R1 — show ip route

C>* 10.0.0.0/28 is directly connected, enp1s0
S>* 10.0.0.16/29 [1/0] via 10.0.0.26, enp4s0
C>* 10.0.0.24/30 is directly connected, enp4s0

R2 — show ip route

S>* 10.0.0.0/28 [1/0] via 10.0.0.25, enp1s0
C>* 10.0.0.16/29 is directly connected, enp3s0
C>* 10.0.0.24/30 is directly connected, enp1s0

C — подключённая сеть, S — статический маршрут, >* — маршрут выбран и установлен в ядро. На ПК должна быть строка S>* 0.0.0.0/0 … via <шлюз>.

Конечная цель — рабочие станции пингуют друг друга. В обычном терминале:

С ПК1

ping -c 3 10.0.0.19
traceroute 10.0.0.19

Прыжки: 10.0.0.3 → 10.0.0.26 → 10.0.0.19

С ПК2

ping -c 3 10.0.0.1
traceroute 10.0.0.1

Прыжки: 10.0.0.17 → 10.0.0.25 → 10.0.0.1

13. Пункт 11. Сохранение (все машины)

sudo vtysh
copy running-config startup-config

Команда вводится в привилегированном режиме (не внутри conf — сначала end). Настройки записываются в /etc/frr/frr.conf.

14. Пункт 12. Перезагрузка и проверка

sudo reboot

После загрузки на каждой машине:

sudo vtysh -c 'show running-config'
sudo vtysh -c 'show ip route'

и снова ping ПК1 ↔ ПК2. Если что-то не поднялось — поправить /etc/frr/frr.conf и перезапустить FRR:

sudo nano /etc/frr/frr.conf
sudo systemctl restart frr

Примерное содержимое /etc/frr/frr.conf (порядок строк и служебные строки в начале могут отличаться):

R1

ip forwarding

interface enp1s0

exit
!
interface enp4s0
 ip address 10.0.0.25/30
exit
!
ip route 10.0.0.16/29 10.0.0.26

R2

ip forwarding
!
interface enp1s0
 ip address 10.0.0.26/30
exit
!
interface enp3s0
 ip address 10.0.0.17/29
exit
!
ip route 10.0.0.0/28 10.0.0.25

ПК1

interface enp4s0
 ip address 10.0.0.1/28
exit
!
ip route 0.0.0.0/0 10.0.0.3

ПК2

interface enp1s0

exit

16. Если не работает

СимптомЧто проверить
apt install frr не находит пакетНет интернета (вузовский кабель, ip -br a, sudo dhclient -v <интерфейс>) или не сделан sudo apt update.
Не пингуется сосед (п. 3)ip -br link — есть ли UP; адрес и маска в show interface brief; кабель в нужном порту.
Адрес из vtysh пропадает или рядом висит лишний 169.254.x.xИнтерфейсом после restore управляет NetworkManager: sudo nmcli device set enp1s0 managed no (свой интерфейс), затем снова назначить адрес в vtysh.
Соседи пингуются, дальние — нетshow ip route: есть ли S>* маршруты; ip forwarding на обоих маршрутизаторах; шлюз по умолчанию на ПК.
Маршрут показан как S без >*Неверный next-hop: адрес соседа не из подключённой сети или сосед недоступен.
traceroute: command not foundНе поставлен в п. 5; можно использовать tracepath 10.0.0.19.
После перезагрузки всё пропалоНе выполнен copy running-config startup-config — настроить заново и сохранить.

17. Кратко для защиты

  • FRR — пакет маршрутизации для Linux; vtysh — единая консоль настройки в стиле Cisco IOS; zebra применяет адреса и маршруты в ядре, staticd обслуживает статические маршруты.
  • Маршрут по умолчанию 0.0.0.0/0 на рабочей станции отправляет все пакеты в чужие сети на шлюз.
  • Статический маршрут на маршрутизаторе указывает, через какой соседний маршрутизатор достижима неподключённая сеть. Маршруты нужны в обе стороны, иначе не вернётся ответ.
  • ip forwarding разрешает пересылку пакетов между интерфейсами (без неё машина не работает как маршрутизатор).
  • running-config — текущая конфигурация в памяти, startup-config — сохранённая (/etc/frr/frr.conf), загружается при старте.
